把 Z Code 变成 OpenAI 兼容 API

本机反向代理：GLM-5.3 / GLM-5.3-Flash 走标准 /v1/chat/completions，凭据零搬运，工具循环与思考档位完整透传。

A local reverse proxy that exposes your Z Code coding plan as an OpenAI-compatible API.

MIT License Go 标准库 · 零依赖 单二进制 ~6MB macOS / Linux / Windows
快速开始 GitHub 仓库 →

特性

🔌OpenAI 完全兼容

/v1/chat/completions、/v1/models；流式 SSE 与非流式聚合双模式，任意 OpenAI SDK / CLI 零改造接入。

🔐凭据零搬运

只读 Z Code 本机配置取 apiKey，不复制、不改写 App 文件；密钥不落仓库、不进 OMP 配置。

🧠签名思考回放

工具循环自动补回带 signature 的 thinking 块——OpenAI 客户端只回显文本，网关替你记住签名。

🎚️思考档位透传

reasoning_effort → output_config.effort，low / medium / high / max 映射到上游；未指定时用配置默认。

🏷️客户端归因

可选 mimic 模式完整镜像 Z Code 归因头与账号 ID，闲时 50% 积分优惠与套餐权益同等生效。

🌐局域网共享

0.0.0.0 监听 + 访问口令：同网段设备共用一个网关，口令一键轮换。

⚡按需启动

OMP 解析凭据时自动拉起网关，取口令永不阻塞（≤2s），无需手工常驻服务。

📦单二进制

纯 Go 标准库实现，无第三方依赖；go build 一步产出，交叉编译随意。

快速开始

1 · 构建并启动

git clone https://github.com/binggao1230/glm-zcode-2api
cd glm-zcode-2api

CGO_ENABLED=0 go build -trimpath \
  -ldflags="-s -w" -o bin/glm-zcode-2api ./cmd/server

# 读取 Z Code 配置、生成访问口令、后台常驻
python3 scripts/omp-gateway.py start

curl -s http://127.0.0.1:7864/healthz

2 · 调用

KEY=$(python3 scripts/omp-gateway.py token)

curl -sN http://127.0.0.1:7864/v1/chat/completions \
  -H "Authorization: Bearer $KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "glm-5.3-flash",
    "messages": [{"role":"user","content":"hi"}],
    "stream": true
  }'

3 · 接入 OMP（oh-my-pi）

# ~/.omp/agent/models.yml
zcode:
  baseUrl: http://127.0.0.1:7864/v1
  api: openai-completions
  apiKey: '!/usr/bin/python3
    ~/projects/glm-zcode-2api/scripts/omp-gateway.py token'
  authHeader: true
  models:
  - id: glm-5.3-flash
    reasoning: true

管理命令

python3 scripts/omp-gateway.py status   # 运行状态
python3 scripts/omp-gateway.py restart  # 重新登录后同步
python3 scripts/omp-gateway.py stop
python3 scripts/omp-gateway.py token    # 打印访问口令

OMP 解析凭据时若网关未运行会自动拉起，无需常驻。

闲时优惠，与 App 同权

新版 GLM Coding Plan 按积分计费，非高峰时段（含周末全天）调用只消耗 50% 标准积分。这类权益按客户端归因判定——网关的 mimic_client 模式（启动器默认开启）把 Z Code 的归因头与账号 ID 原样带给上游，代理流量与 App 内流量同等对待：

user-agent: ZCode/3.14.1· x-zcode-agent: glm· http-referer: zcode.z.ai· x-os-version: 27.0.0· x-client-timezone: Europe/Paris· metadata.user_id: <账号 ID>

版本号自动读取 Z Code.app，账号 ID 自动从套餐 JWT 解出，时区默认探测本机、可用 upstream.client_timezone 指定。

FAQ

报 429 / 1310「已达使用上限」？
计划配额确实用完了，错误文案原样透传（含重置时间）。等重置后自动恢复；网关不做任何伪装或绕过。
HTTP 401？
上游密钥失效——在 Z Code App 里重新登录，然后 python3 scripts/omp-gateway.py restart。网关每次请求前会自动重读 Z Code 配置，多数情况无需重启。
访问口令是什么？泄漏了怎么办？
口令在 ~/.local/state/glm-zcode-2api/client.key（0600），等同账号额度的使用权。泄漏后删除该文件再 restart 即自动轮换，客户端无需改配置。
局域网其他设备怎么用？
网关默认监听 0.0.0.0:7864。其他设备把 baseUrl 指到 http://<本机IP>:7864/v1，apiKey 填本机 client.key 内容即可。只要 /healthz 不鉴权，其余接口全部要求口令。
思考能关掉吗？为什么关了还有 reasoning？
可以：reasoning_effort: "off" 或配置 thinking.enabled=false，网关发 thinking.type=disabled。实测上游在 disabled 下仍会输出一小段思考，网关如实透传、不做抹除。
支持图片输入吗？
已实现 OpenAI image_url（data URL / http(s) URL / base64）到 Anthropic image block 的转换；glm-5.3-flash 声明支持视觉，端到端效果以实际使用为准。
