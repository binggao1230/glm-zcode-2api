特性

Features

OpenAI 完全兼容

/v1/chat/completions、/v1/models；流式 SSE 与非流式聚合双模式，任意 OpenAI SDK / CLI 零改造接入。

OpenAI-compatible

/v1/chat/completions and /v1/models; streaming SSE and aggregated non-streaming. Any OpenAI SDK/CLI works unchanged.

凭据零搬运

只读 ZCode 本机配置取 apiKey，不复制、不改写 App 文件；密钥不落仓库、不进 OMP 配置。

Zero credential copying

Reads the apiKey from the local ZCode config. No copies, no app-file rewrites; no key in the repo or OMP config.

签名思考回放

工具循环自动补回带 signature 的 thinking 块——OpenAI 客户端只回显文本，网关替你记住签名。

Signed thinking replay

Tool loops automatically get the signature-bearing thinking block re-injected — clients only echo visible text, the gateway remembers signatures for you.

思考档位透传

reasoning_effort → output_config.effort，low / medium / high / max 映射到上游；未指定时用配置默认。

Thinking effort pass-through

reasoning_effort → output_config.effort mapping (low / medium / high / max); config defaults apply when unset.

客户端归因

可选 mimic 模式完整镜像 ZCode 归因头与账号 ID，闲时 50% 积分优惠与套餐权益同等生效。

Client attribution

Optional mimic mode mirrors the ZCode attribution headers and account ID, so off-peak 50% credit discounts apply equally.

局域网共享

0.0.0.0 监听 + 访问口令：同网段设备共用一个网关，口令一键轮换。

LAN sharing

0.0.0.0 listener with a mandatory access token: share one gateway across devices, rotate the token in one command.

按需启动

OMP 解析凭据时自动拉起网关，取口令永不阻塞（≤2s），无需手工常驻服务。

On-demand startup

OMP starts the gateway automatically when resolving credentials; token resolution never blocks (≤2s).

单二进制

纯 Go 标准库实现，无第三方依赖；go build 一步产出，交叉编译随意。

Single binary

Pure Go standard library, no third-party dependencies; one go build, cross-compile freely.

快速开始

Quick Start

$ curl -sN http://127.0.0.1:7864/v1/chat/completions \
    -H "Authorization: Bearer $KEY" -H "Content-Type: application/json" \
    -d '{"model":"glm-5.3-flash","messages":[{"role":"user","content":"hi"}],"stream":true}'

data: {"choices":[{"delta":{"role":"assistant"}}]}
data: {"choices":[{"delta":{"reasoning_content":"让我想想…"}}]}
data: {"choices":[{"delta":{"content":"你好！"}}]}
data: {"choices":[{"delta":{},"finish_reason":"stop"}]}
data: [DONE]

流式 SSE：角色帧 → reasoning_content 思考增量 → 内容增量 → finish_reason → [DONE]。

1 · 构建并启动

git clone https://github.com/binggao1230/glm-zcode-2api
cd glm-zcode-2api

CGO_ENABLED=0 go build -trimpath \
  -ldflags="-s -w" -o bin/glm-zcode-2api ./cmd/server

# 读取 ZCode 配置、生成口令、后台常驻
python3 scripts/omp-gateway.py start

python3 scripts/omp-gateway.py restart  # 重新登录后同步
python3 scripts/omp-gateway.py stop

闲时优惠，与 App 同权

Off-peak discounts, same treatment as the app

新版 GLM Coding Plan 按积分计费，非高峰时段（含周末全天）调用只消耗 50% 标准积分。这类权益按客户端归因判定——网关的 mimic_client 模式（启动器默认开启）把 ZCode 的归因头与账号 ID 原样带给上游，代理流量与 App 内流量同等对待：

The new GLM Coding Plan is credit-based: calls during off-peak hours (including weekends) consume only 50% of standard credits. These perks are decided by client attribution — with mimic_client (enabled by the launcher by default), the gateway mirrors ZCode's attribution headers and account ID, so proxied traffic gets the same treatment:

user-agent: ZCode/3.14.1· x-zcode-agent: glm· http-referer: zcode.z.ai· x-os-version: 27.0.0· x-client-timezone: Europe/Paris· metadata.user_id: <account id>

版本号自动读取 ZCode.app，账号 ID 自动从套餐 JWT 解出，时区默认探测本机、可用 upstream.client_timezone 指定。

The version is read from ZCode.app's Info.plist, the account ID is decoded from the plan JWT, and the timezone is detected from the host by default (override with upstream.client_timezone).

FAQ

报 429 / 1310「已达使用上限」？
计划配额确实用完了，错误文案原样透传（含重置时间）。等重置后自动恢复；网关不做任何伪装或绕过。
HTTP 401？
上游密钥失效——在 ZCode 里重新登录后 restart。网关每次请求前会自动重读 ZCode 配置，多数情况无需重启。
访问口令是什么？泄漏了怎么办？
口令在 ~/.local/state/glm-zcode-2api/client.key（0600），等同账号额度的使用权。泄漏后删除该文件再 restart 即自动轮换，客户端无需改配置。
局域网其他设备怎么用？
网关默认监听 0.0.0.0:7864。其他设备把 baseUrl 指到 http://<本机IP>:7864/v1，apiKey 填本机 client.key 内容即可。除 /healthz 外全部接口要求口令。
思考能关掉吗？为什么关了还有 reasoning？
可以：reasoning_effort: "off" 或配置 thinking.enabled=false，网关发 thinking.type=disabled。实测上游在 disabled 下仍会输出一小段思考，网关如实透传、不做抹除。
OMP 报 No API key found for zcode？
不是要你配 key——是取口令的命令失败了。常见于网关正在重启、或 OMP 会话缓存了旧目录路径；重启该 OMP 会话即可。新版启动器取口令永不阻塞（≤2s）。
支持图片输入吗？
已实现 OpenAI image_url（data URL / http(s) URL / base64）到 Anthropic image block 的转换；glm-5.3-flash 声明支持视觉，端到端效果以实际使用为准。
HTTP 429 / 1310 "usage limit reached"?
Your plan quota is genuinely exhausted; the error (including reset time) passes through verbatim. It recovers automatically after the reset — the gateway never disguises or bypasses anything.
HTTP 401?
The upstream key is stale — sign into ZCode again, then restart. The gateway re-reads the ZCode config on every request, so most changes need no restart.
What is the access token? What if it leaks?
It lives at ~/.local/state/glm-zcode-2api/client.key (0600) and equals usage rights to your plan. If leaked, delete the file and restart — a new token is minted and clients need no changes.
How do other LAN devices use it?
The gateway listens on 0.0.0.0:7864. Point other devices at http://<host-ip>:7864/v1 with the host's client.key as the apiKey. Everything except /healthz requires the token.
Can thinking be turned off? Why is there still reasoning?
Yes: reasoning_effort: "off" or thinking.enabled=false sends thinking.type=disabled. The upstream still emits a short thinking trace when disabled; the gateway passes it through untouched.
OMP says "No API key found for zcode"?
You are not supposed to configure a key — the token command failed. Typical while the gateway restarts, or when an OMP session cached an old path; restart that OMP session. The launcher never blocks on token resolution (≤2s).
Image inputs?
OpenAI image_url parts (data URLs / http(s) URLs / base64) are translated to Anthropic image blocks; glm-5.3-flash declares vision support — verify end-to-end with your workload.
